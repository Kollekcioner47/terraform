Материалы прежней версии курса.

Эти файлы не используются на занятиях. Они оставлены только для истории:
в новой версии курса их содержание полностью заменено, а всё полезное
и всё ошибочное разобрано в новых практиках с пометками ИСПРАВЛЕНО.

ВАЖНОЕ ПРЕДУПРЕЖДЕНИЕ ДЛЯ ТОГО, КТО ОТКРОЕТ ЭТИ ФАЙЛЫ

Тексты в каталоге archive/ сохранены как есть, включая неработающие
команды, чужие идентификаторы облака и каталога, пароли открытым

ЧТО ИМЕННО БЫЛО НЕ ТАК В ПРЕЖНЕЙ ВЕРСИИ

Этот список — основа пометок ИСПРАВЛЕНО в новых практиках. Каждый
пункт проверен на живом облаке или по документации провайдера.

  Не работало вовсе

    * les1-1: выводы второй машины ссылались на первую —
      yandex_compute_instance.vm-1 в output для vm-2 (копирование
      без правки). Студент видел адрес первой машины дважды.

    * les2: в метаданных ключ записан как "${file("id_ed25519.pub")}"
      без имени пользователя. Формат метаданных — "пользователь:ключ",
      без имени пользователя вход по ключу не настраивается.

    * les5: скрипт cloud-init узнавал внешний адрес запросом
      http://169.254.169.254/latest/meta-data/public-ipv4.
      Это адрес службы метаданных AWS. В Яндекс Облаке служба
      метаданных отвечает по другому пути
      (computeMetadata/v1/instance/network-interfaces/0/access-configs/0/external-ip)
      и требует заголовок Metadata-Flavor: Google. Скрипт не работал,
      и в файле index.html не появлялось адреса.

    * les5: правило egress группы безопасности ограничивало исходящий
      трафик портом 80. Установка пакетов идёт по HTTPS (443) и по
      нескольким другим портам, поэтому установка apache2 из скрипта
      не проходила. Плюс в правилах использовался protocol = "ANY"
      там, где нужен "TCP".

    * les3: acl = "public-read" заменялся на acl = "public-admin",
      когда объекты не загружались. Значения "public-admin" у бакета
      не существует; верный путь для публичного сайта — политика
      доступа к бакету (yandex_storage_bucket_policy), а сами ACL
      в провайдере объявлены устаревшими.

  Устарело

    * image_id = "fd807ed79a4kkqfvd1mb" — образ Ubuntu 16.04.
      Актуальные семейства: ubuntu-2404-lts, ubuntu-2604-lts и другие;
      жёсткий идентификатор заменяется источником данных по семейству.

    * platform_id = "standard-v1" (les5) — эту платформу нельзя
      использовать в зонах ru-central1-d и ru-central1-e.

    * zone = "ru-central1-c" — такой зоны доступности больше нет.
      Актуальны ru-central1-a, -b, -d (документация рекомендует -d
      для новых проектов) и -e.

    * required_version = ">= 0.13" и отсутствие ограничения версии
      провайдера. Для хранилища состояния в Object Storage нужен
      Terraform 1.6.3 и новее, а нативная блокировка состояния
      (use_lockfile) — 1.10 и новее.

    * yandex_mdb_mongodb_cluster с вложенными блоками database и user:
      такие блоки объявлены устаревшими, базы и пользователи
      описываются отдельными ресурсами. Версия СУБД 6.0 из примера
      тоже устарела.

    * ${...} вокруг каждого значения (les4, les5, les7) — синтаксис
      времён Terraform 0.11. Начиная с 0.12 интерполяция нужна только
      внутри строки: subnet_id = yandex_vpc_subnet.subnet-1.id.

    * deletion_protection = "true" (les4) — строка вместо логического
      значения.

    * Модули подключались по адресу git@github.com:... (les9) —
      для этого нужен SSH-ключ, добавленный в GitHub. Документация
      использует HTTPS, а модули библиотеки terraform-yc-modules
      в публичном реестре Terraform не опубликованы.

  Чего не было совсем

    * Хранения состояния вне локального файла: ни backend, ни блокировки,
      ни миграции состояния, ни импорта уже существующих ресурсов.
    * Переменных и структуры проекта: значения были вписаны в текст
      конфигурации, включая идентификаторы облака и каталога автора
      курса и пароль пользователя базы данных открытым текстом.
    * Пометки про секреты: ключ сервисного аккаунта лежал в каталоге
      проекта (C:/tf_cloud/authorized_key.json), файл состояния
      terraform.tfstate вместе с каталогом .terraform — прямо
      в материалах курса.
    * Разбора стоимости и уборки ресурсов после занятия.
